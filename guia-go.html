4.2 Interfaces

O que é? Uma interface em Go é um contrato de comportamento. Ela define um conjunto de métodos (funções) que um tipo precisa ter para "satisfazer" a interface. Pense nela como uma especificação: "quem quiser ser um X, precisa saber fazer Y e Z".
Por que usar? Interfaces permitem escrever código flexível e desacoplado. Você pode criar funções que aceitam qualquer tipo que tenha determinados métodos, sem se importar com o tipo concreto. Isso facilita testes, mocks e a criação de código reutilizável.

Como funciona na prática

Você define uma interface com os métodos que precisa. Depois, qualquer struct que tiver esses métodos automaticamente "implementa" a interface — sem precisar declarar explicitamente (diferente de Java ou C#).

Exemplo Básico: Interface Animal

// 1. Defina a interface: quem quiser ser um Animal precisa ter o método Som()
type Animal interface {
    Som() string
}

// 2. Crie structs que satisfazem a interface (implicitamente!)
type Cachorro struct{}
type Gato struct{}

// 3. Implemente o método Som() para cada struct
func (Cachorro) Som() string { return "Au au!" }
func (Gato) Som() string    { return "Miau!" }

// 4. Crie uma função que aceita QUALQUER Animal
func emitirSom(a Animal) {
    fmt.Println(a.Som())
}

// 5. Use!
func main() {
    emitirSom(Cachorro{}) // Au au!
    emitirSom(Gato{})    // Miau!
}
Como usar (passo a passo):
  1. Defina a interface com os métodos que você precisa
  2. Crie structs que tenham esses métodos
  3. Use a interface como tipo em funções, parâmetros e retornos
  4. Passe qualquer struct que satisfaça a interface

Interface Vazia (interface{})

A interface vazia interface{} (ou any em Go 1.18+) não tem métodos, então qualquer tipo a satisfaz. É útil quando você não sabe o tipo que vai receber.

// Aceita qualquer tipo
func imprimir(v interface{}) {
    fmt.Println(v)
}

// Com any (Go 1.18+)
func imprimirAny(v any) {
    fmt.Println(v)
}

// Exemplo prático: verificar tipo
func descrever(v interface{}) {
    switch v := v.(type) {
    case int:
        fmt.Println("É um inteiro:", v)
    case string:
        fmt.Println("É uma string:", v)
    default:
        fmt.Println("Tipo desconhecido")
    }
}

Interfaces Embutidas (Composição)

Você pode "herdar" métodos de outras interfaces para criar interfaces maiores:

type Leitor interface {
    Ler() string
}

type Escritor interface {
    Escrever(s string)
}

// LeitorEscritor tem Ler() E Escrever()
type LeitorEscritor interface {
    Leitor
    Escritor
}

Interfaces do Pacote Padrão

Go tem várias interfaces úteis prontas. As mais comuns:

InterfaceMétodosUso

io.ReaderRead([]byte) (int, error)Leitura de dados

// Exemplo: implementando fmt.Stringer
type Produto struct {
    Nome  string
    Preco float64
}

func (p Produto) String() string {
    return fmt.Sprintf("%s: R$ %.2f", p.Nome, p.Preco)
}

// Agora fmt.Println usa String() automaticamente
p := Produto{"Notebook", 3500.00}
fmt.Println(p) // Notebook: R$ 3500.00
Dica: Prefira interfaces pequenas e específicas. Em Go, é comum criar interfaces com apenas 1 ou 2 métodos. Isso facilita a implementação e os testes.

4.3 Goroutines e Concorrência

O que é? Uma goroutine é uma função que executa de forma concorrente (em paralelo) com outras funções. Pense nela como uma "thread leve" — você pode criar milhares delas sem consumir muita memória.
Por que usar? Para executar tarefas em paralelo sem bloquear o programa principal. Ideal para: chamadas de API, processamento de dados, tarefas em background, servidores que lidam com múltiplos clientes.

Como usar

Basta colocar a palavra-chave go antes de uma função:

// Inicia uma goroutine (não bloqueia)
go minhaFuncao()

// Goroutine com função anônima
go func() {
    fmt.Println("Executando em paralelo")
}()

WaitGroup: Esperando Goroutines Terminarem

O problema: o programa principal pode terminar antes das goroutines. A solução é usar sync.WaitGroup:

func main() {
    var wg sync.WaitGroup

    // Diga quantas goroutines você vai esperar
    wg.Add(1)

    go func() {
        defer wg.Done() // Marca como terminada ao final
        fmt.Println("Goroutine completa")
    }()

    wg.Wait() // Bloqueia até todas terminarem
    fmt.Println("Todas terminaram!")
}
Como usar (passo a passo):
  1. Crie um var wg sync.WaitGroup
  2. Chame wg.Add(1) antes de cada goroutine
  3. Dentro da goroutine, use defer wg.Done()
  4. Chame wg.Wait() onde precisa esperar

Exemplo Prático: Processamento Paralelo

func processar(id int, wg *sync.WaitGroup) {
    defer wg.Done()
    fmt.Printf("Iniciando tarefa %d\n", id)
    time.Sleep(2 * time.Second) // Simula trabalho
    fmt.Printf("Tarefa %d concluída\n", id)
}

func main() {
    var wg sync.WaitGroup

    for i := 1; i <= 3; i++ {
        wg.Add(1)
        go processar(i, &wg)
    }

    wg.Wait()
    fmt.Println("Todas as tarefas concluídas!")
}
Atenção: Goroutines não retornam valores diretamente. Para passar dados entre goroutines, use channels (próxima seção).

4.4 Channels

O que é? Um channel é um tubo de comunicação entre goroutines. Ele permite que uma goroutine envie dados e outra receba, de forma segura e sincronizada.
Por que usar? Para passar dados entre goroutines de forma segura, sem race conditions. Channels são a forma idiomática de sincronizar e comunicar em Go.

Como usar

// 1. Criar um channel
ch := make(chan int)

// 2. Enviar valor (em uma goroutine)
go func() {
    ch <- 42  // Envia 42 para o channel
}()

// 3. Receber valor (bloqueia até ter dados)
valor := <-ch  // Recebe o valor do channel
fmt.Println(valor) // 42

Channel com Buffer

Um channel com buffer pode armazenar N valores antes de bloquear:

// Channel com buffer de 2
chBuf := make(chan string, 2)

chBuf <- "a"  // Não bloqueia (buffer tem espaço)
chBuf <- "b"  // Não bloqueia
// chBuf <- "c"  // Bloquearia! Buffer cheio

fmt.Println(<-chBuf) // "a"
fmt.Println(<-chBuf) // "b"

Select: Múltiplos Channels

O select permite esperar em múltiplos channels simultaneamente:

ch1 := make(chan string)
ch2 := make(chan string)

go func() { ch1 <- "um" }()
go func() { ch2 <- "dois" }()

for i := 0; i < 2; i++ {
    select {
    case msg1 := <-ch1:
        fmt.Println("ch1:", msg1)
    case msg2 := <-ch2:
        fmt.Println("ch2:", msg2)
    }
}

Range sobre Channel

Você pode iterar sobre um channel até ele ser fechado:

func produtor(ch chan int) {
    for i := 0; i < 5; i++ {
        ch <- i
    }
    close(ch) // Fecha o channel
}

func main() {
    ch := make(chan int)
    go produtor(ch)

    for v := range ch {
        fmt.Println(v) // 0, 1, 2, 3, 4
    }
}
Como usar (passo a passo):
  1. Crie um channel com make(chan Tipo)
  2. Envie dados com ch <- valor
  3. Receba dados com valor := <-ch
  4. Use select para múltiplos channels
  5. Feche com close(ch) quando terminar

4.5 Tratamento de Erros

O que é? Em Go, erros são valores. Não existem exceções como em Java ou Python. Funções que podem falhar retornam um valor error como último retorno.
Por que usar? Para lidar com falhas de forma explícita e previsível. Você sempre sabe quando uma função pode falhar e precisa verificar o erro.

Como usar

// 1. Função que retorna erro
func lerArquivo(caminho string) ([]byte, error) {
    dados, err := os.ReadFile(caminho)
    if err != nil {
        return nil, fmt.Errorf("erro ao ler %s: %w", caminho, err)
    }
    return dados, nil
}

// 2. Verificar o erro
dados, err := lerArquivo("config.json")
if err != nil {
    log.Fatal(err) // Loga e encerra o programa
}

// 3. Criar erro personalizado
var ErrNaoEncontrado = errors.New("item não encontrado")

// 4. Verificar tipo de erro
if errors.Is(err, os.ErrNotExist) {
    fmt.Println("Arquivo não existe")
}

// 5. Extrair erro específico
var pathErr *os.PathError
if errors.As(err, &pathErr) {
    fmt.Printf("Erro no caminho: %s\n", pathErr.Path)
}
Como usar (passo a passo):
  1. Funções que podem falhar retornam (valor, error)
  2. Sempre verifique if err != nil
  3. Use fmt.Errorf para criar erros com contexto
  4. Use errors.Is e errors.As para verificar erros específicos
Dica: Use %w no fmt.Errorf para "embrulhar" erros e manter a cadeia de erros: fmt.Errorf("contexto: %w", err)

4.6 Defer, Panic e Recover

O que é?
  • defer: Adia a execução até o final da função
  • panic: Interrompe o programa imediatamente (como uma exceção)
  • recover: Captura um panic e permite recuperar o controle
Por que usar?
  • defer: Para garantir que recursos sejam liberados (fechar arquivos, conexões, etc.)
  • panic: Para erros irrecuperáveis que não devem ser ignorados
  • recover: Para evitar que o programa quebre completamente

Defer

func main() {
    defer fmt.Println("1 - executado por último")
    defer fmt.Println("2 - penúltimo")
    fmt.Println("3 - primeiro")
}
// Saída:
// 3 - primeiro
// 2 - penúltimo
// 1 - executado por último

// Uso comum: fechar arquivo
func processarArquivo(nome string) error {
    f, err := os.Open(nome)
    if err != nil {
        return err
    }
    defer f.Close() // Fecha ao final da função

    // ... processa o arquivo ...
    return nil
}

Panic e Recover

func dividir(a, b int) (resultado int) {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("Recuperado de panic:", r)
            resultado = 0
        }
    }()
    return a / b  // panic se b == 0
}

func main() {
    fmt.Println(dividir(10, 2)) // 5
    fmt.Println(dividir(10, 0)) // Recuperado de panic: runtime error: integer divide by zero, depois 0
}
Como usar (passo a passo):
  1. defer: Coloque antes de qualquer chamada que deve rodar no final
  2. panic: Use apenas para erros irrecuperáveis
  3. recover: Use dentro de uma função com defer para capturar panics

4.7 Generics (Go 1.18+)

O que é? Generics permitem escrever funções e tipos que funcionam com qualquer tipo, sem perder a segurança de tipos. É como "tipos parametrizados".
Por que usar? Para evitar código duplicado. Em vez de escrever MaxInt, MaxFloat, MaxString..., você escreve Max[T] uma vez.

Função Genérica

// T é um "placeholder" para qualquer tipo
func Max[T constraints.Ordered](a, b T) T {
    if a > b {
        return a
    }
    return b
}

// Uso
fmt.Println(Max(3, 5))       // 5 (int)
fmt.Println(Max(3.14, 2.71)) // 3.14 (float64)
fmt.Println(Max("a", "b")) // "b" (string)

Tipo Genérico

// Lista que funciona com qualquer tipo
type Lista[T any] struct {
    itens []T
}

func (l *Lista[T]) Adicionar(item T) {
    l.itens = append(l.itens, item)
}

func (l *Lista[T]) Obter(indice int) T {
    return l.itens[indice]
}

// Uso
numeros := Lista[int]{}
numeros.Adicionar(1)
numeros.Adicionar(2)

nomes := Lista[string]{}
nomes.Adicionar("Ana")
nomes.Adicionar("Bruno")

Restrições (Constraints)

Você pode limitar quais tipos podem ser usados:

ConstraintSignificado
anyQualquer tipo
constraints.OrderedTipos comparáveis (int, float, string)
constraints.SignedInteiros com sinal
constraints.IntegerQualquer inteiro
~intint e tipos baseados em int (ex: type MeuInt int)
Como usar (passo a passo):
  1. Defina um tipo genérico com [T any] ou [T constraints.Ordered]
  2. Use T como tipo dentro da função/struct
  3. Ao chamar, especifique o tipo: Max[int](3, 5) ou deixe inferir: Max(3, 5)

4.8 Manipulação de Arquivos e JSON

O que é? Operações de leitura/escrita em arquivos e conversão entre structs Go e JSON.
Por que usar? Para persistir dados, ler configurações, e comunicar com APIs (que geralmente usam JSON).

Escrever Arquivo

// Escrever string em arquivo
conteudo := []byte("Olá, Go!")
err := os.WriteFile("arquivo.txt", conteudo, 0644)
if err != nil {
    log.Fatal(err)
}

// Permissões: 0644 = dono lê/escreve, outros leem

Ler Arquivo

// Ler arquivo inteiro
dados, err := os.ReadFile("arquivo.txt")
if err != nil {
    log.Fatal(err)
}
fmt.Println(string(dados))

JSON: Struct → JSON (Marshal)

type Usuario struct {
    Nome  string `json:"nome"`
    Email string `json:"email"`
}

u := Usuario{Nome: "Ana", Email: "ana@email.com"}

// Converte struct para JSON
jsonBytes, err := json.Marshal(u)
if err != nil {
    log.Fatal(err)
}
fmt.Println(string(jsonBytes))
// {"nome":"Ana","email":"ana@email.com"}

JSON: JSON → Struct (Unmarshal)

// JSON recebido (ex: de uma API)
jsonStr := `{"nome":"Bruno","email":"bruno@email.com"}`

// Converte JSON para struct
var u2 Usuario
err := json.Unmarshal([]byte(jsonStr), &u2)
if err != nil {
    log.Fatal(err)
}
fmt.Println(u2.Nome) // Bruno

Tags JSON

As tags permitem personalizar o nome dos campos no JSON:

type Produto struct {
    ID        int     `json:"id"`
    Nome      string  `json:"nome"`
    Preco     float64 `json:"preco"`
    Estoque   int     `json:"-"`              // Ignora no JSON
    Descricao string  `json:"descricao,omitempty"` // Omite se vazio
}
Como usar (passo a passo):
  1. Defina uma struct com tags JSON
  2. Use json.Marshal para struct → JSON
  3. Use json.Unmarshal para JSON → struct
  4. Sempre verifique erros

4.9 Testes

O que é? Testes automatizados verificam se seu código funciona como esperado. Go tem suporte nativo a testes sem precisar de bibliotecas externas.
Por que usar? Para garantir que seu código funciona corretamente, facilitar refatorações, e documentar como o código deve se comportar.

Escrevendo Testes

Crie um arquivo com sufixo _test.go no mesmo pacote:

// arquivo: main_test.go
package main

import "testing"

// Toda função de teste começa com Test
func TestSomar(t *testing.T) {
    resultado := somar(2, 3)
    esperado := 5
    if resultado != esperado {
        t.Errorf("somar(2,3) = %d; esperado %d", resultado, esperado)
    }
}

Testes de Tabela (Table-Driven Tests)

Padrão comum em Go para testar múltiplos casos:

func TestSomarTabela(t *testing.T) {
    testes := []struct {
        nome     string
        a, b     int
        esperado int
    }{
        {"positivos", 1, 2, 3},
        {"zeros", 0, 0, 0},
        {"negativo", -1, 1, 0},
    }

    for _, tt := range testes {
        t.Run(tt.nome, func(t *testing.T) {
            if got := somar(tt.a, tt.b); got != tt.esperado {
                t.Errorf("somar(%d,%d) = %d; esperado %d", tt.a, tt.b, got, tt.esperado)
            }
        })
    }
}

Rodando Testes

# Rodar todos os testes
go test ./...

# Rodar com verbose
go test -v ./...

# Rodar teste específico
go test -v -run TestSomar

# Ver cobertura
go test -cover ./...
Como usar (passo a passo):
  1. Crie um arquivo nome_test.go
  2. Importe "testing"
  3. Escreva funções TestXxx(t *testing.T)
  4. Use t.Errorf para reportar falhas
  5. Rode com go test ./...

4.10 Context (Timeout e Cancelamento)

O que é? O pacote context permite passar prazos, cancelamento e valores entre funções e goroutines. É essencial para controlar o tempo de execução de operações.
Por que usar? Para implementar timeouts, cancelar operações desnecessárias, e passar dados de request (como IDs de usuário) em aplicações web.

Context com Timeout

func buscarDados(ctx context.Context) (string, error) {
    select {
    case <-ctx.Done():
        return "", ctx.Err() // Timeout ou cancelamento
    case <-time.After(2 * time.Second):
        return "dados obtidos", nil
    }
}

func main() {
    // Cria um context que cancela após 1 segundo
    ctx, cancel := context.WithTimeout(
        context.Background(),
        1*time.Second,
    )
    defer cancel() // Sempre chame cancel!

    resultado, err := buscarDados(ctx)
    if err != nil {
        fmt.Println("Timeout!") // buscarDados demorou 2s, mas timeout é 1s
    }
}

Context com Cancelamento Manual

ctx, cancel := context.WithCancel(context.Background())
defer cancel()

go func() {
    select {
    case <-ctx.Done():
        fmt.Println("Cancelado!")
    case <-time.After(5 * time.Second):
        fmt.Println("Completou!")
    }
}()

time.Sleep(2 * time.Second)
cancel() // Cancela a goroutine

Context com Valores

// Adiciona valores ao context
ctx := context.WithValue(context.Background(), "userID", 123)

// Recupera valores
userID := ctx.Value("userID").(int)
fmt.Println(userID) // 123
Como usar (passo a passo):
  1. Crie um context com context.Background() ou context.TODO()
  2. Adicione timeout: context.WithTimeout(ctx, tempo)
  3. Passe o context como primeiro parâmetro: funcao(ctx context.Context)
  4. Verifique ctx.Done() para saber se foi cancelado
  5. Sempre use defer cancel()

5. Projetos Práticos

Projeto 1: CLI de Lista de Tarefas (Todo List)

Iniciante Intermediário

Descrição: Um gerenciador de tarefas via terminal que permite adicionar, listar, marcar como concluída e remover tarefas. Os dados devem ser persistidos em um arquivo JSON.

Funcionalidades

  • Adicionar nova tarefa com descrição e prioridade
  • Listar todas as tarefas (pendentes e concluídas)
  • Marcar tarefa como concluída
  • Remover tarefa
  • Filtrar por status ou prioridade
  • Persistência em arquivo JSON

Conceitos Praticados

  • Structs e métodos
  • Manipulação de JSON
  • Leitura/escrita de arquivos
  • Flags e argumentos de CLI (pacote flag)
  • Tratamento de erros
  • Slices e maps

Exemplo de Uso

./todo add "Estudar Go" --prioridade alta
./todo list
./todo complete 1
./todo remove 2

Projeto 2: Servidor de Encurtador de URLs

Intermediário

Descrição: Uma API REST que recebe URLs longas e gera códigos curtos únicos. Ao acessar o código curto, o usuário é redirecionado para a URL original. Inclui contador de acessos.

Funcionalidades

  • POST /encurtar — recebe URL, retorna código curto
  • GET /{codigo} — redireciona para URL original
  • GET /stats/{codigo} — retorna estatísticas de acesso
  • Validação de URL
  • Geração de códigos únicos (base62)
  • Persistência em memória (map) ou arquivo

Conceitos Praticados

  • HTTP server (pacote net/http)
  • JSON encoding/decoding
  • Structs e interfaces
  • Tratamento de erros HTTP
  • Testes de handlers
  • Concorrência (mutex para acesso ao map)

Exemplo de Uso

curl -X POST -d '{"url":"https://exemplo.com"}' localhost:8080/encurtar
# Resposta: {"codigo":"abc123","url_curta":"/abc123"}

curl -L localhost:8080/abc123
# Redireciona para https://exemplo.com

Projeto 3: API REST de Blog com Autenticação

Intermediário Avançado

Descrição: Uma API REST completa para um blog com autenticação JWT, CRUD de posts e comentários, middleware de autorização, e banco de dados SQLite.

  • Middleware de autenticação e logging
  • Validação de dados

  • gorm.io/gorm + sqlite3 (ORM)
  • golang-jwt/jwt (autenticação)

Conceitos Praticados

  • Arquitetura em camadas (handler, service, repository)
  • Interfaces para desacoplamento
  • Middlewares
  • JWT e segurança
  • Banco de dados e migrations
  • Testes com mocks
  • Tratamento de erros centralizado
  • Context para timeout e valores
